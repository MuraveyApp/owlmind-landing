No mystery box: the checklist, the timeline, the report and the fix-verification loop.

Which Vulnerabilities We Look For

Every audit starts from the money: who can move value, under what checks, and what happens when those checks are raced, replayed or fed hostile input. On that path we hunt:

  • ✓ Reentrancy and cross-function repeated calls
  • ✓ Flash-loan and price-oracle manipulation
  • ✓ Access-control and role-escalation flaws
  • ✓ Overflow, underflow and precision loss
  • ✓ Signature replay, missing nonce or deadline
  • ✓ Upgradeable-proxy and initializer mistakes
  • ✓ Front-running and missing slippage protection
  • ✓ Centralization: one key that can rug or pause forever

How the Audit Runs

Scope is frozen first: commit hash, chains, in-scope contracts, admin roles. Then a manual line-by-line review of every value-moving function, plus static and symbolic tooling for the rest. Every critical candidate gets a working proof-of-concept — a reproduction, not a screenshot. Findings are ranked by impact and walked through with your team.

How Long It Takes and What It Costs

A single contract or token takes 1–2 weeks. A full protocol — core, periphery, scripts and deploy config — takes 3–5 weeks. Timeline and price scale with code size, mechanism novelty and integrations. You get a fixed quote before work starts; scope changes are re-quoted, never billed silently.

What Lands in the Report

  • ✓ Executive summary for investors
  • ✓ Every finding: root cause, severity, affected code path
  • ✓ Working proof-of-concept for critical and high issues
  • ✓ Code-level fix, not a vague recommendation
  • ✓ Residual risk and centralization notes

Re-Check After Fixes

After your team ships fixes, we re-scan the changed code free of charge and confirm each remediation in an updated report — so the final PDF reflects the code you actually deploy. Every audit includes 30 days of support.

Bottom line: a serious audit is a reproducible process — frozen scope, manual review of value paths, working PoCs, a report partners can act on, and a free re-check after fixes. Anything less is a checkbox.

FAQ

Can you audit before the code is finished?

A partial review of a frozen branch helps, but a final report needs a commit hash that will not move.

Do you publish the report?

Only if you choose to. Many teams publish it for listing and investor trust — timing is yours.

What if a finding is disputed?

We walk through the PoC with your engineers. If the issue is by-design or unreachable, we record the reasoning and adjust severity — in writing.
