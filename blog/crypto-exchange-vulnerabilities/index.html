Top Crypto Exchange Vulnerabilities

Six bug classes drain exchanges year after year — each has a known fix.

1. Reentrancy (Repeated Call)

The contract transfers funds before it updates the balance. A malicious receiver calls withdraw again while the old balance is still recorded — and drains the vault in one transaction.

  • ✓ Checks-Effects-Interactions: update state first, transfer last
  • ✓ Reentrancy guard on every value-moving function

2. Flash-Loan Attacks

The attacker borrows huge capital inside one transaction, bends a protocol (vote, pool price, collateral), profits and repays — all atomically. Own capital is not needed.

  • ✓ Time-weighted average price instead of spot quotes
  • ✓ Per-block caps on minting, borrowing and large swaps

3. Oracle Price Manipulation

If pricing runs on a thin pool or a single feed, one large swap moves the price and liquidates honest users. The exchange logic is fine — the price input is the bug.

  • ✓ Several independent feeds, median of sources
  • ✓ Deviation circuit-breaker: pause on sharp moves

4. Withdrawal Race Conditions

Two withdrawal requests pass the balance check before either debits. Both succeed on the same balance — a double-spend. Same shape in refunds and bonus claims.

  • ✓ One DB transaction: check and debit atomically
  • ✓ Idempotency keys so a retry cannot pay twice

5. Key and Secret Leakage

Hot-wallet keys, withdrawal API tokens and admin passwords leak through JS bundles, public .env files, CI logs and support chats. One leaked key is a full payout queue.

  • ✓ Sign payouts in HSM or MPC — never on app servers
  • ✓ Secret scanning in CI; no secrets in front-end bundles

6. KYC Bypass

Selfie-only checks, reusable document uploads and race conditions in the verification state machine let one person open many accounts — for laundering or bonus abuse.

  • ✓ Document authenticity checks plus active liveness
  • ✓ Server-side state machine — no client-trusted status flags

FAQ

Which of these is most common?

Withdrawal races and key leakage. Boring, outside the contract code, and they pay out instantly.

Do flash-loan defenses slow a protocol?

No. TWAP windows add at most one block of latency — invisible to users, decisive against atomic manipulation.
