Топ уязвимостей криптобирж

Шесть классов ошибок опустошают биржи — у каждого есть известное решение.

Бесплатная консультация

1. Повторный вызов (reentrancy)

Контракт переводит средства ДО обновления баланса. Вредоносный получатель снова вызывает вывод, пока старый баланс ещё записан, и выкачивает хранилище за одну транзакцию.

  • ✓ Порядок «проверка-эффект-взаимодействие»: сначала состояние, потом перевод
  • ✓ Защита от повторного входа на каждую функцию с переводом

2. Атаки мгновенными займами

Атакующий берёт огромный капитал внутри одной транзакции, гнёт протокол (голосование, цена пула, залог), забирает прибыль и возвращает заём — атомарно. Своих денег не нужно.

  • ✓ Средняя цена за окно времени вместо мгновенной
  • ✓ Лимиты на блок: выпуск, заём, крупные обмены

3. Подмена цен через оракулы

Если цена берётся из тонкого пула или одной ленты, один крупный обмен двигает её и ликвидирует честных пользователей. Логика исправна — ошибка во входной цене.

  • ✓ Несколько независимых источников, медиана
  • ✓ Предохранитель по отклонению: пауза на резком скачке

4. Гонки при выводе средств

Два запроса на вывод проходят проверку баланса до списания. Оба успешны по одному балансу — двойной расход. Та же форма у возвратов и бонусов.

  • ✓ Одна транзакция базы: проверка и списание атомарно
  • ✓ Ключи идемпотентности, чтобы повтор не заплатил дважды

5. Утечка ключей и секретов

Ключи горячего кошелька, токены вывода и админ-пароли утекают через JS-бандлы, публичные .env, логи CI и чаты поддержки. Один утёкший ключ = целая очередь выплат.

  • ✓ Подпись выплат в HSM или MPC — никогда на прикладных серверах
  • ✓ Поиск секретов в CI; никаких секретов во фронтовых бандлах

6. Обход KYC

Проверка по селфи, повторное использование документов и гонки в автомате верификации дают одному человеку много аккаунтов — для отмывания или накрутки.

  • ✓ Проверка подлинности документа плюс активная проверка живости
  • ✓ Серверный конечный автомат — без флагов статуса с клиента

Что даёт проверка

Целевая проверка шести классов выше — контракты, вывод, ключи, KYC — с работающим доказательством каждой критической проблемы и исправлением на уровне кода. Начинайте с денежных путей.

Вопросы

Что из этого встречается чаще всего?

Гонки при выводе и утечка ключей. Скучные, вне кода, платят мгновенно.

Делает ли защита от flash-loan протокол медленным?

Нет. Окна TWAP добавляют максимум одну блоковую задержку — для пользователя незаметно, для атомарной манипуляции решающе.
